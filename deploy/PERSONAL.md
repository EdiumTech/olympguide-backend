# API личного поступления

Миграции 017–019 добавляют стипендии, общий календарь с ревизиями, личные планы,
необязательные поля существующих дипломов, профиль поступления и разборы правил.
Старые API дипломов и данные сохраняются. Миграции запускаются перед новой версией
API. В архиве static `personal-2026-20260908` находятся сведения и оригиналы источников;
порядок импорта: основной каталог 2026, затем `--personal-only` существующего
`deploy/import_admissions.py`. Основной повторный импорт требует повторного импорта
разборов. До него неразобранные правила дают ручную проверку.

## Контракт

Все пути относительно `/api/v1`. Личные маршруты используют существующую cookie
`session`; `user_id` не принимается из запроса. Чужие записи в новых API возвращают
404. Проверка владельца также добавлена в старые запросы льгот/вузов по ID диплома.

| Метод и путь | Назначение |
|---|---|
| GET `/scholarships?university_id=…&program_id=…` | Выплаты с условиями, суммами/null, периодом и источниками; область программы только явная |
| GET `/personal/catalog` | Числовые ID олимпиад/профилей и программ с ключами Release |
| GET `/calendar/events` | Активные события; фильтры `kind`, `season`, `olympiad_key`, `program_key` |
| GET `/user/calendar` | Личный план, свежая версия источника, `dates_changed`, `source_active` |
| POST `/user/calendar` | `{ "event_id": "стабильный ключ" }`; повторный запрос сохраняет существующий план |
| POST `/user/calendar/custom` | `{ "client_key": "UUID", "event": {…} }`; UUID повторяется при повторе одного запроса |
| PUT `/user/calendar/:id` | `status`, `note`, `acknowledge`, необязательный `event` только для своего события |
| DELETE `/user/calendar/:id` | Удалить только собственную запись плана |
| GET/PUT `/user/admission-profile` | `{ "admission_year": 2026, "exams": [{"subject":"физика","score":85,"year":2026}] }` |
| POST `/user/diploma/` | Старые `olympiad_id`, `class`, `level` + необязательные `award_year`, `olympiad_year`, `profile`, `result` |
| PUT `/user/diploma/:id/details` | Те же сведения своего диплома; пустые необязательные значения — `null` |
| GET `/user/diplomas/` | Старый ответ дополнен `olympiad_id` и новыми полями |
| GET `/user/recommendations` | `diploma_id`, `status`, `benefit`, `q`, `limit` 1–100, `offset` |

`class` — класс заданий 1–11. `level` — степень I/II/III (1/2/3), не уровень
олимпиады. `result`: `winner`, `prize_winner`, `participant` или null.
Учебный год — `2025/2026`, год диплома и год поступления — независимые поля.

План: `planned`, `registered`, `participating`, `completed`, `skipped`.
Виды событий: `registration_open`, `registration_close`, `qualifying`, `final`,
`results`, `appeal`, `documents_open`, `documents_close`, `admission`, `custom`.
Типы времени: `all_day` + `start_date`; `date_range` + `start_date`/`end_date`
включительно; `timed` + `starts_at`/необязательный `ends_at` (RFC3339, конец исключён);
`undated` без дат. IANA `timezone` обязателен; смещение RFC3339 сверяется с зоной.

Рекомендации возвращают `items`, `total`, `message`, год и пагинацию. Каждая
программа содержит отдельные `assessments`: статус, вид преимущества, причину,
проверки и `source_rule`. Статусы: `eligible`, `confirmation_required`, `ineligible`,
`manual_review`. Проверка не использует правила другого года; неизвестная часть
не считается отказом или обещанием. Положительный вывод относится к введённым
данным и не означает гарантированное зачисление.

Разборы импортируются вместе с полным снимком исходного правила. Несовпадение с
актуальным JSON останавливает импорт. Если источник изменился позднее, API прекращает
автоматически применять разбор. Поддерживаются связанные AND/OR условия, конкретные
классы, результаты, сроки дипломов, профили и действующие результаты ЕГЭ.
Специальные исключения, внутренние испытания, неподтверждённые пары и большинство
ВсОШ/международных правил в этом наборе требуют ручной проверки.

## Веб и эксплуатация

Локальный просмотр static использует `/backend` как узкий посредник к этому API.
Cookie остаётся в отдельном браузере с HttpOnly/SameSite; проверяются Origin,
loopback Host, размер и разрешённый путь. Регистрация нового аккаунта остаётся
в приложении; веб поддерживает вход существующего аккаунта. Избранное веба
по-прежнему хранится локально, дипломы/ЕГЭ/план — в backend.

Push, APNs и любые автоматические уведомления отсутствуют. Миграции и импорт не
должны запускаться в production автоматически из проверки PR. Перед ручным
production-импортом существующий загрузчик выполняет backup, если передан `--host`.

## Проверка

`go test ./...` в `api`. Для интеграционных тестов задайте `OLYMPGUIDE_TEST_DSN`
на одноразовую PostgreSQL с миграциями и обоими наборами данных. Проверяются
четыре статуса, точные пороги/альтернативы, годы, область действия, изменение
источника, владельцы дипломов/профилей/планов, идемпотентность, сохранение отметок
и даты/DST. Python-тест настоящего SQL-импорта находится в static, в
`data_loader/admissions/tests/test_personal_import.py`.
# РСОШ 2026/2027: обновление каталога

Для ветки исправлений карточек требуется миграция `020-rsosh_registry.sql`
после миграций 015–019. Затем из актуального `olympguide-static`:

```sh
python deploy/import_admissions.py --static-repo ../olympguide-static --registry-only --output .private/rsosh.sql
```

Команда проверяет Release/SHA-256, официальный DOCX и все 303 профиля 79
олимпиад. SQL импортируется обычным процессом после резервной копии.
`--registry-only` обновляет отдельные записи РСОШ и проверенную почту вузов;
ID старых олимпиад, дипломы, избранное и личный календарь сохраняются.
Повторный импорт персонального набора также требует миграции 020.

`GET /olympiads` и список профилей теперь ограничены РСОШ 2026/2027.
Добавлены `academic_year`, `registry_status`, `subjects`. На 08.09.2026 источник
имеет статус **draft**, не approved. `admission_year` новых записей пуст;
правила 2026 не переносятся. Прямой `GET /olympiad/:id` и персональный каталог
оставляют исторические ID доступными. В выборе диплома показывается сезон
либо год исходного каталога правил, чтобы различать совпадающие названия.

Каталог направлений исключает направления без программ. Вузы олимпиады
должны иметь ту же связь с программами, которую использует запрос льгот;
одно правило без связи больше не создаёт пустой раскрывающийся вуз.
Фильтры GORM сохраняют возвращённый запрос. Изменение популярности олимпиады
обновляет только счётчик и не записывает пустые строки в nullable-поля реестра.

Проверено локально с PostgreSQL 16: миграция, повторный импорт, `go test ./...`,
`go vet ./...`. Изменения не развёрнуты в production автоматически.
